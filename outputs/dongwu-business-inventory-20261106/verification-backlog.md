## 3. 每项证据包最低要求

此为下一阶段工作规范提案，不是原系统规则：记录本地时间与时区、账号角色（不记凭据）、页面路由/标题、操作目标的资源类型与 ID、请求方法/路径/非敏感 payload、HTTP 状态、业务码、响应字段、操作前后快照、结论等级与反例。截图辅助证明页面语境，接口 JSON 证明数据；二者不能互相替代。

只读补采可继续复用本目录临时采集器；写操作必须选用业务方可控的测试对象或环境。无须为本次已授权的只读查询再次请求授权，但本次报告不把未来写验证视为已经完成。

## 4. 进入本体建模的门槛与建议顺序

1. **先身份和术语**：完成 VB-01/02/03/04，输出概念与源资源映射、稳定标识符、关系基数和反例。其余概念允许候选状态，不假装全部已定义。
2. **再流程和约束**：完成 VB-05/06/08/09/11/12，输出按对象分离的状态字典、命令前后置条件、工艺适用规则、审批与异常路径；保留配置版本与证据。
3. **最后核算和覆盖**：完成 VB-07/10/15/16/17，确定数量/重量/时间/权限和历史快照口径；通过 VB-18/19/20 补齐外围领域后，再决定新平台开发范围。

上述为**待验证的下一阶段提案**。本阶段不决定技术栈，不创建新业务表，不把源 API 资源数量直接转换为实体数量，也不迁移或修复既有数据库。
