# 业务操作边界与验收场景

日期：2026-11-06。范围和BR-01～08见[核心本体](core-business-model.md)，源证据C/H编号见[字段映射](process-and-source-map.md#6-证据索引)。本轮仅读取，没有执行保存配置、报工、审核、重制、封存、撤销或发运。

## 1. 操作边界

表内“业务要求”来自用户确认或已见样本；“建议留痕”及未证实的前后条件属于**待验证／设计建议**，不能标为原系统已实现。

| 操作 | 对象与已确认要求 | 当前证据等级 | 后续需核对的条件/副作用 |
|---|---|---|---|
| 创建/维护项目与订单 | 管理首期业务范围、订单及构件需求 | 范围已验证〔用户〕；源读实体已验证 | 必填、编号规则、删除保护、导入幂等及订单商业含义 |
| 维护生产特征 | 维护构件适用流程所用字典 | 目录及入口已验证〔C03/C05〕 | 重命名、停用、码值大小写、既有记录引用；不能默默改变历史原码 |
| 维护工序与特征关联 | 通过配置定义工序适用范围 | 机制已验证〔用户〕；探伤/涂装关联页已验证〔C04〕 | 新增/删除关联的权限及生效时点、在制品是否重新计算 |
| 维护工艺流程 | 组织节点和连线，供计划及执行使用 | 图与设计入口已验证〔H02/H03〕 | 保存校验、版本、并发、循环/不可达图处理、历史追溯 |
| 排产/下发生产 | 为构件组织计划、流程和执行范围 | 源计划/排产/构件关系已验证〔前轮及C01〕 | 同一构件重复下发、撤回、跨单/跨项目约束及角色 |
| 执行/完成工序 | 依据该构件的生产特征和工艺配置执行应做工序 | 规则已验证〔BR-07/08〕；完成快照已验证〔C01〕 | 执行前置工序、异常回退、人工跳过、补录与修改的权限及审计 |
| 报检、探伤、质检 | 对适用工序记录业务结果；FXC不需要探伤 | 已验证〔用户+配置〕；前轮结果快照0～4已读取 | 部分通过、拒绝重提、复检次数、单头汇总、是否需要签名附件 |
| 确认成品入库 | 该构件应走工序完成，以涂装完成作为入库动作 | 已验证〔BR-04/07/08〕 | 回退/更正后的库存影响、历史补录和清库存归类；不另增加未经确认的仓库点收条件 |
| 补件/重制与原状态封存 | 新构件身份，原构件生产状态封存，历史进度保留 | 已验证〔BR-02/03〕；源操作/关联尚待验证 | 创建、审核还是下发时触发封存；次数、理由、谁可发起、是否可解除、库存/发运影响 |
| 包装/发运 | 维护包箱和成员、发运引用；数量层级明确 | 已验证〔前轮完整成员及PDF〕 | 已完成资格、散件混装、一件多包、发运撤回、删除/拆包历史 |

## 2. 工序适用与完成的判定边界

**已验证业务机制**：生产特征及工艺配置确定哪些工序需要执行。**待验证／模型建议**：将“适用性依据”和“执行结果”分开保存，解释规则如下。

| 条件 | 业务解释 | 等级 |
|---|---|---|
| 配置及业务规则明确该工序不适用 | 不要求产生该工序完成记录，不阻断适用路径完成 | 已验证原则：BR-07/08，FXC探伤样本 |
| 工序适用且有完成记录 | 可以作为该构件流程完成的证据之一 | 已验证源字段存在；字段与实际动作的完整契约仍待验证 |
| 工序适用但无完成记录 | 尚不能确认该工序完成 | 较高可信推断；不能因总体is_complete=1而伪造完成事实 |
| 特征、配置来源或适用性未知 | 标为待核对，保留原始记录和查询语境 | 待验证／保守映射建议；不能把未知当不适用 |
| 临时人工跳过 | 与按配置不适用区分；需要单独依据 | 待验证；用户没有确认任意跳过权限和审核条件 |
| 流水线结束 | 半成品完成 | 已验证用户规则；不计成品入库 |
| 清库存流程或旧成品库记录 | 保留原完成事实，进入历史映射核对 | 已验证源记录；目标库存解释仍待验证 |

**待验证／建议留痕**：构件源身份、使用的生产特征原值、工艺与工序关联证据、执行节点、动作时间、记录时间、操作者、证据来源。具体存储字段和配置版本方案属于后续设计，不在本轮实现。

## 3. 可复核的验收场景

“已通过”仅指本轮只读证据核对，不表示新平台已有功能或业务写测试通过。

| 场景 | 应能表达的结果 | 本轮状态与证据 |
|---|---|---|
| 普通钢构全部适用节点完成并涂装完成 | 能识别成品完成正例，保留原时间与流程依据 | 已验证样本：5984、7097，共2条，C01 `/requests/3,5` |
| 发现场FXC未做探伤，其他适用工序完成并涂装完成 | 不因探伤空记录误报未完成，不伪造探伤通过 | 已验证用户规则及27条样本：9097，C01 `/requests/11`、C04、C05 |
| 涂装显示列仅含部门，尚无完成记录 | 不将非空显示字符串当完工 | 已验证20条反例：9154，C01 `/requests/1` |
| 流水线转运结束且is_complete=1 | 识别半成品完成并排除成品入库 | 已验证259条反例及用户分类：8819，C01 `/requests/7` |
| 旧数据is_complete=1但complete_time=0 | 保留已见完成证据，不把0转成真实业务日期 | 已验证87条历史反例：H04 |
| 完成时间和结束节点时间差1秒 | 两个原值保留，不擅自覆盖 | 已验证865391：C06 `timeMismatches` |
| 同编号补制 | 原件和新件不同身份，原生产状态封存，新件独立推进 | 业务规则已确认；缺真实原件关联/封存操作证据，未完成写测试 |
| 构件缺特征或配置版本不明 | 不自动补成GJG或默认跳过全部工序 | 待验证／映射验收建议；本轮未制造异常数据 |
| 修改工序关联后，既有计划如何解释 | 可说明旧配置与新配置的生效边界 | 待验证，未保存/更改任何配置 |
| 包箱跨订单、打印行合并多个ID | 保留成员身份，统计包箱数/成员数/打印行数分别计算 | 前轮已有对账证据，沿用结论 |

## 4. 进入写验证前需要的最小条件

以下是**待验证／执行前提**，并非当前要求用户立刻答复：选择可控测试项目/对象、确定角色与允许动作、明确如何辨认原件和补制件。先对每个命令记录前状态及上下游引用，再执行动作，核对响应和后状态。没有可控对象时继续只读分析，不试改实际生产单。

用户已确认的首期范围、新构件身份、原状态封存、入库定义、流水线排除和配置驱动工序，不再反复作为基础疑问提出。需要补的是源系统承载方式、异常路径及操作权限。
